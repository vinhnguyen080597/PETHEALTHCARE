## 3. Environment Variables & Platform Sync

### A. Vercel (Frontend)
To ensure Server-Side Rendering (SSR), canonical tags, OpenGraph metadata, and dynamic routing generate valid URLs, the following environment variables were updated:

| Variable Name | Type | Value / Purpose |
| :--- | :--- | :--- |
| `NEXT_PUBLIC_SITE_ORIGIN` | **Config** | `https://www.pethub.com.vn` |
| `NEXT_PUBLIC_API_ORIGIN` | **Config** | Render Backend Service URL |
| `NEXT_PUBLIC_SUPABASE_URL` | **Secret/Config** | Supabase Project URL |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | **Secret** | Supabase Anonymous Key |

> **Key Takeaway / Troubleshooting Note (Vercel):**
> * Variables with the `NEXT_PUBLIC_` prefix must be assigned the **Config** type (not Secret). If configured as `Secret`, Vercel throws a public prefix exposure warning.
> * If a variable was initially saved as `Secret`, the Vercel UI locks the option to toggle to `Config`. The solution is to **delete the variable and re-create it as Config**.
> * Every update to `NEXT_PUBLIC_` variables requires a **full project Redeploy** on Vercel so Next.js can embed the values during the build phase.

### B. Render (Backend API)
To support cross-origin request handling and backend-generated links (e.g., verification callbacks), Render environment variables were updated:

| Variable Name | Value |
| :--- | :--- |
| `CORS_ORIGINS` | `https://pethub.com.vn,https://www.pethub.com.vn` |
| `PUBLIC_SITE_ORIGIN` | `https://pethub.com.vn` (Updated from `pet-marketplace.org`) |

## 5. Transactional Email & SMTP Setup (Gmail Issue & Resolution)

### Problem Description
Initially, transactional emails (OTP verification, registration) sent from Supabase displayed `vinhnho1997@gmail.com` as the sender, despite configuring `pethubvietnam@gmail.com` as the `Sender email address` in Supabase SMTP Settings. Additionally, testing custom credentials produced HTTP 500 Internal Server Errors.

### Root Cause Analysis
1. **Sender Identity Override:** Gmail SMTP enforces strict identity matching. If the SMTP Username belongs to Account A (`vinhnho1997@gmail.com`), Google overrides any custom "From" header to prevent spoofing.
2. **500 Error Triggers:** 
   * **Account Mismatch:** Trying to authenticate with `vinhnho1997@gmail.com` as Username while using an App Password generated by `pethubvietnam@gmail.com`.
   * **Formatting Issues:** Including raw spaces in Google’s 16-character App Password (e.g., `jdas ltof bbgu iwdi`).

### Resolution Steps (Google Account & Supabase Sync)
1. **Enable 2-Step Verification:**
   * Logged into `pethubvietnam@gmail.com` -> Security Settings -> Completed 2-Step Verification via SMS/Phone.
2. **Generate App Password:**
   * Navigated to `myaccount.google.com/apppasswords`.
   * Created a dedicated App Password named `Supabase SMTP`.
3. **Supabase SMTP Configuration:**
   * **Host:** `smtp.gmail.com`
   * **Port:** `465`
   * **Sender Email:** `pethubvietnam@gmail.com`
   * **Sender Name:** `Pethub Vietnam`
   * **Username:** `pethubvietnam@gmail.com`
   * **Password:** `jdasltofbbguiwdi` (Spaces removed completely).

> **Future Recommendation:**
> Gmail SMTP imposes strict daily quotas (100–500 emails/day) and can flag automated transactional traffic as spam. For scale, the system should transition to a dedicated Transactional Mail Provider (e.g., **Resend** or **SendGrid**) with custom domain alignment (`no-reply@pethub.com.vn`) via DKIM/SPF records on PA Vietnam.
